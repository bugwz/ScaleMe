# 数据、同步与隐私

ScaleMe 采用本地优先设计。用户无需账户即可完成成员管理、设备测量、记录浏览和趋势分析；Apple 健康集成需要用户主动开启并授权。

## 本地文件

应用将配置与健康测量分开保存到沙盒中的 `ScaleMe/` 目录：

| 文件 | 内容 | 保护方式 |
| --- | --- | --- |
| `configuration.json` | 分层保存的成员、关联设备、界面与功能配置 | iOS Complete File Protection |
| `data.json` | 带成员及设备归属的版本化数据记录 | iOS Complete File Protection |

两个文件均位于 `Application Support/ScaleMe/`，不标记为排除备份，因此在用户开启系统设备备份且未单独排除本应用时，可随 iCloud 或电脑备份迁移到新设备。应用不使用自管 AES 密钥加密这两个文件，避免数据文件恢复后因设备限定密钥未迁移而无法读取。iOS 文件数据保护仍会在设备锁定时保护内容。

设备备份不等于多设备实时同步：当前应用未启用 CloudKit 或 iCloud Documents。自动恢复主要发生在新设备设置或整机恢复流程；用户也可以随时使用应用内的明文 JSON 导出与导入。

项目仍处于发布前快速迭代阶段；开发期数据结构变化时可以重置本地数据，不通过迁移层维持未发布格式。

## 导入与导出

“设置 → 数据管理”默认以组合文件处理完整配置与测量档案，也保留两类文件的独立导入导出：

- 配置导入经用户确认后替换本机配置。
- 测量导入按记录 ID 合并，避免简单覆盖现有档案。
- 组合文件是一个顶层含 `config` 与 `data` 字段的 JSON 对象；两字段分别包含完整配置文件与数据文件对象。导入时会一次校验两部分，确认后替换配置并合并测量记录。
- 配置文件与数据文件均为带 `schemaVersion` 的明文 JSON，可跨设备备份恢复、分享和导入；数据文件通过 `references` 保存成员、设备与来源，`records` 中使用对应下标。应用内部文件额外受 iOS Complete File Protection 保护。
- 配置导出包含顶层格式版本，并按成员、设备、通信、通用设置、测量、Apple 健康、仪表盘和小组件分组。
- 数据文件按 `updatedAt`、`references`、`columns`、`records` 和 `deletedRecords` 排列。每条有效记录使用由 `columns` 定义的位置数组，并在格式化 JSON 中保持单行显示。删除记录只保留原 ID、时间、体重、来源和设备 ID 组成的最小标记，用于阻止体重秤再次下发同一历史记录；体脂、阻抗等完整测量内容不会保留在删除标记中。
- `references` 对成员 UUID、设备信息和记录来源去重，记录行只保存对应下标；行末连续缺失的可选值会省略，中间缺失值以 `null` 保持列位置。
- 手动导出的数据文件保留两空格缩进和换行，不使用去空白或文件压缩。
- 手动导出与本地存储使用同一字段层级与固定书写顺序。
- 应用内部及导出文件中的成员、设备和测量 ID 均使用带连字符的标准 UUID。

导出文件可能包含个人资料、设备归属和健康记录，应由用户自行选择可信的保存和传输位置。

## Apple 健康

Apple 健康集成是可选的仅写入链路。用户开启后，需要明确选择同步成员以及数据可信的设备。当前约束为：

- 只写入所选成员来自所选设备的后续稳定体重。
- 只有设备明确提供体脂率时才写入体脂率。
- 不读取健康数据，不补传历史记录。
- 不写入手动记录、来源未关联的记录或应用推导的身体成分。

授权和样本落库必须在签名 iPhone 上验证。关闭应用内同步并不等同于删除已经由用户授权写入 Apple 健康的历史样本。

## 模拟数据

模拟模式提供多成员、多设备和不等间隔历史记录，用于浏览完整产品体验：

- 不替换真实资料或正式测量档案。
- 成员、设备、排序和记录修改会保存在模拟档案，可独立导入和导出。
- 模拟数据不会写入 Apple 健康。
- 模拟体脂秤的稳定记录在生成或保存时使用正式计算流程，并保存结果快照；导出包含这些结果，调整成员资料不会自动重算历史结果。
- 模拟体重秤不补算身体成分；缺少必要输入的指标仍显示空值，皮下脂肪、蛋白质和骨骼肌不由其他成分推造。

## 设备诊断

诊断采集需要用户在设备设置页主动开启，只针对当前设备在内存中保留有限数量的广播与连接事件。内容可能包括设备 UUID、本地名称、序列号、服务、特征、原始载荷、写入回执与测量摘要。

诊断不会自动写文件或上传。只有用户主动导出后才离开内存；报告可能包含敏感标识、测量值或协议数据，不应公开分享，也不应包含设备绑定密钥。

## 健康与医学边界

消费级体脂秤通常通过生物电阻抗和用户档案估算身体成分。体脂、肌肉、水分、蛋白质、骨量、内脏脂肪和基础代谢等指标只适合趋势参考，不能用于诊断、治疗或临床判断。

实现与界面遵循以下原则：

- 保留并明确标识设备直接上报的原始值。
- 原始设备/协议值优先，默认估算在已识别的体脂测量保存时完成，并与设备原始值分开持久化；不会作为设备体脂率写入 Apple 健康。普通体重秤、手动和健康导入记录不触发估算。
- 默认计算规则优先使用设备或协议直接提供的体脂率。缺少体脂率且有主阻抗时，采用[2015 年足间生物电阻抗研究](https://pubmed.ncbi.nlm.nih.gov/25986468/)中的回归方程估算：`FFM = 13.055 + 0.204 × W + 0.394 × H² / Z − 0.136 × age + 8.125 × sex`，`BF% = 100 × (1 − FFM / W)`。其中 W 为体重（kg），H 为身高（cm），Z 为主阻抗（Ω），男性 sex 取 1、女性取 0。原研究使用健康亚洲人群的 50 kHz 足间阻抗；该成人分支按小数年龄 18–75 岁选用。原研究样本 BMI 为 15.8–43.1；应用不以 BMI 拦截计算，但范围外属于未经验证的外推；其他年龄分支见下文。100–2000 Ω 是应用的输入校验范围，不代表研究验证范围。去脂体重必须大于 0 且小于体重，异常结果不会被强行截断。
- 当前默认映射将主阻抗作为所选模型的 Z/R 输入。这是明确标注的实验性设备适配假设，AFU 等设备的频率和通道语义尚未完成匹配验证，不能据此声称官方算法、国际通用标准或已验证准确度。第二路原样保留，不替代第一路、不取平均、不当作电抗。记录的 `applicationEstimate` 保存公式类型、具体模型、小数年龄、实际使用的阻抗及无法估算原因；`calculatedMetrics` 保存身高、出生日期、生理性别及按指标名称组织的结果（含 BMI、质量／比例换算及静息能量）。两者一并写入本地文件及独立／组合 JSON 导出；无法计算的指标不生成数值。历史结果不随资料编辑自动变化；重新分配成员时按新成员资料重新计算并保存。读取或导入只有原始数据、尚无计算快照的记录时，按其所属成员资料补算一次并保存；已经存在的快照不自动重算，缺失阻抗不会借用其他记录补齐。
- 所有默认补算（包括基础代谢）均要求稳定的体脂秤记录具有有效主阻抗。缺少或主阻抗无效时仅保留设备/协议直接提供的指标及其质量比例换算；不使用 BMI 估算体脂。BMI 作为独立指标，不参与体脂公式或补算准入。
- 去脂体重等于体重减去脂肪量，不等同于肌肉量。静息能量估算限 19–78 岁，采用 `10 × kg + 6.25 × cm − 5 × age + C`（男性 C 为 5，女性为 −161），并与设备直接提供的基础代谢值分开。来源见[成人静息能量研究](https://pubmed.ncbi.nlm.nih.gov/2305711/)。
- Sun 分支优先使用该研究的独立总水分模型，仅对缺少水分的字段补算；若结果不合理，不再用另一公式覆盖失败。其余满 18 岁且缺少水分时，水分量按 `0.732 × FFM` 估算，水分率为水分量除以体重再乘以 100；恒定水合比例是一项模型假设，并非个人实测值。参考[去脂体重水合研究](https://pubmed.ncbi.nlm.nih.gov/10232621/)。
- 仅满 18 岁时，骨量、肌肉量和内脏脂肪采用未经验证的应用经验规则：骨量为 `0.052 × FFM`；肌肉量为 `FFM − 骨量`（设备骨量优先），实际是无骨瘦体重代理值，不是骨骼肌测量；内脏脂肪应用指数为 `min(30, max(1, (BF% − 12) × 0.45 + age × 0.03))`，不等同于厂商等级或真实内脏脂肪量。质量占比统一为质量除以体重再乘以 100。这些系数由应用定义，未从官方截图反推出厂商算法，也不是上述文献验证的公式。
- 缺少基础代谢时采用 [FAO/WHO/UNU 报告 Table 5.2](https://www.fao.org/4/y5686e/y5686e07.htm) 的 Schofield 分年龄公式 `BMR = a × W + b`，单位 kcal/天，W 为 kg。按 0–2、3–9、10–17、18–29、30–59、60 岁及以上分段：男性 `(a,b)` 为 `(59.512,-30.4)`、`(22.706,504.3)`、`(17.686,658.2)`、`(15.057,692.2)`、`(11.472,873.1)`、`(11.711,587.7)`；女性为 `(58.317,-31.1)`、`(20.315,485.9)`、`(13.384,692.6)`、`(14.818,486.6)`、`(8.126,845.6)`、`(9.082,658.5)`。设备值优先；不设老年年龄上限不意味着所有高龄或患病人群均已验证。它不包含活动及生长全部能量需求，不是每日摄入建议。
- 展示估算会在成员资料修改或记录重新归属后重新计算，原始值和文件格式保持不变。首页、测量、详情和趋势不展示估算徽标或提示，估算规则、来源与适用边界集中在“数据说明”中展示。缺少必要输入、超出适用范围或结果异常时不估算，蛋白质等未建模指标不在本规则中。适用边界参见[生物电阻抗应用指南](https://pubmed.ncbi.nlm.nih.gov/15380917/)。
- 配置和测量文件均以 `schemaVersion 1` 作为当前格式基线。应用已经发布，现有用户数据不能按开发期数据处理，也不能通过重置存储规避兼容问题。版本号不承载开发迭代次数，也不能证明旧文件已经完成迁移。早期同版本文件仍可能包含失效字段或来源无法追溯的补算值；不得仅凭版本号将其认定为当前格式或可靠测量证据。本次调整不会自动删除或重写现有文件。
- 不为纯体重设备伪造身体成分，也不以占位项目暗示支持。
- 不记录健康测量、个人档案或蓝牙绑定密钥到普通日志。

主应用和小组件包含隐私清单，声明不追踪且无向开发者收集的数据类型。当前源码未发现必需理由 API 的使用；文件导入仅查询所选文件的大小，不访问文件时间戳。未虚构 UserDefaults 等未使用 API 的理由声明。每次新增 API 或依赖后都应重新核查最终归档。小组件趋势视图标记为隐私敏感内容，由系统根据显示环境决定遮挡。

正式发布前仍需发布并核验隐私政策 URL、完成设备兼容矩阵实测、App Store 隐私申报与最终归档隐私报告检查。本地处理不等同于向开发者收集数据，主动导出和系统健康同步仍必须在政策中说明。

参考：[Apple 隐私清单格式检查](https://developer.apple.com/documentation/technotes/tn3181-debugging-invalid-privacy-manifest)、[数据收集声明](https://developer.apple.com/documentation/technotes/tn3184-adding-data-collection-details-to-your-privacy-manifest)。

### 全年龄计算与输入

- 年龄按出生日期与测量日期计算；未来出生日期不产生估算。各年龄保留设备提供的指标及可直接推导的质量、比例；不再由某个成人体脂公式的年龄或 BMI 范围阻止独立的基础代谢计算。
- 全年龄基础处理不代表每项身体成分均有全年龄模型。阻抗体脂已扩展为 3.9–94 岁内的分段实验性规则，不能用儿童 BMI 公式替代阻抗计算。小于 3.9 岁和大于 94 岁仍无默认阻抗体脂模型，未成年人不使用成人固定水合比例及骨量、肌肉、内脏脂肪经验规则。
- 身高输入支持 20–250 cm，此范围是输入校验而非研究适用范围。未满 2 岁填写卧位身长，之后填写站立身高。当前记录按成员当前身高计算，未保存历史身高快照，历史 BMI 重算不能代替儿童生长随访。未实现早产儿校正年龄；早产儿、孕期、运动员及患病人群需专门评估。
- WHO BMI 数据离线包含男女 0–1856 日及 61–228 月 LMS 参数。超过逐日表后以 `日龄 / 30.4375` 换算月龄，对相邻月 LMS 作线性插值，这是应用的插值实现。切点为 `M × (1 + L × S × z)^(1/L)`，L 为 0 时使用指数形式。19 岁起切换成人切点。
- `Tools/HealthReference/GenerateWHOBodyMassReference.py` 从 WHO 原始 XLSX 生成 `WHOBodyMassReferenceData.swift`；生成文件记录四张官方表的来源和 SHA-256，未包含用户数据。[WHO 生长指标解释](https://www.who.int/news-room/questions-and-answers/item/child-growth-standards)说明儿童 BMI 分级。

### 分年龄阻抗计算规则

年龄 A 按测量日期计算：已满周岁加上距上次生日的日数除以本生日年度的日数，避免把小数年龄区间粗略当成整岁。W 为 kg，H 为 cm，Z 为主阻抗 Ω。任何分支的 FFM 必须有限、严格大于零且小于体重；体脂率为 `100 × (1 − FFM/W)`。不截断负体脂或过大体脂，不在失败后挑选另一条公式求出看起来正常的结果。

| 应用选择区间 | 模型与公式 | 原研究与适配条件 |
| --- | --- | --- |
| `0 ≤ A < 3.9` | 保留设备指标、BMI 和分年龄基础代谢；不外推阻抗体脂 | 婴儿研究不构成站立式体脂秤的通用模型；不把“处理全年龄输入”表述为“所有指标全年龄经过验证” |
| `3.9 ≤ A < 4.9` | Schaefer：`FFM = 0.65 H²/Z + 0.68 A + 0.15` | [原研究](https://pubmed.ncbi.nlm.nih.gov/8065848/)为 3.9–19.3 岁四电极全身测量；代入消费级足到足通道是未经验证的路径适配 |
| `4.9 ≤ A ≤ 10.9` | Tyrrell：`FFM = 0.31 H²/Z + 0.17 H + 0.11 W + 0.942 T − 14.96`；男 T=2、女 T=1 | [原研究](https://www.nature.com/articles/0801531)使用足到足阻抗，82 名儿童；公式亦列于[中国儿童交叉验证研究 Table 2](https://pmc.ncbi.nlm.nih.gov/articles/PMC4245105/)，不能把路径接近等同于 AFU 验证 |
| `10.9 < A < 12` | Schaefer：`FFM = 0.65 H²/Z + 0.68 A + 0.15` | [原研究](https://pubmed.ncbi.nlm.nih.gov/8065848/)为 3.9–19.3 岁四电极全身测量；代入消费级足到足通道是未经验证的路径适配 |
| `12 ≤ A < 18` | Sun：男 `FFM = −10.68 + 0.65 H²/Z + 0.26 W + 0.02 Z`；女 `FFM = −9.53 + 0.69 H²/Z + 0.17 W + 0.02 Z` | [原研究](https://pubmed.ncbi.nlm.nih.gov/12540391/)覆盖 12–94 岁，使用全身 50 kHz 电阻；未知足到足 Z 不能视为已证实等价的 R |
| `18 ≤ A ≤ 75` | Wu：本节前述阻抗公式，不设 BMI 准入条件 | 保留现有成人足到足分支，年龄系数改用小数年龄 |
| `75 < A ≤ 94` | Sun：男 `FFM = −10.68 + 0.65 H²/Z + 0.26 W + 0.02 Z`；女 `FFM = −9.53 + 0.69 H²/Z + 0.17 W + 0.02 Z` | [原研究](https://pubmed.ncbi.nlm.nih.gov/12540391/)覆盖 12–94 岁，使用全身 50 kHz 电阻；未知足到足 Z 不能视为已证实等价的 R |
| `A > 94` | 保留设备指标、BMI 和分年龄基础代谢；不外推阻抗体脂 | 婴儿研究不构成站立式体脂秤的通用模型；不把“处理全年龄输入”表述为“所有指标全年龄经过验证” |

模型选择及区间衔接是应用规则，不是文献共同验证的一条连续模型。切换公式可能产生数值跳变；不进行无依据的平滑混合，也不能把跳变解释为身体突然变化。并未根据收到的设备通道自动识别频率或路径；所有默认映射仍为实验性适配。

Sun 分支的缺失水分采用同研究：男 `TBW = 1.203 + 0.449 H²/Z + 0.176 W`，女 `TBW = 3.747 + 0.450 H²/Z + 0.113 W`。TBW 为升，显示质量按约 1 kg/L 换算；必须大于零且小于所采用的去脂体重。设备已经提供体脂时仍可独立补算缺失水分，但不覆盖设备体脂或水分，不为其他儿童分支套用成人 0.732 比例。

计算先检查稳定测量、体脂设备能力、体重、身高、出生日期；再检查主阻抗。内部区分缺少主阻抗、输入异常、年龄无模型和结果不合理。主阻抗为空时第二路不能代替；不回退 BMI，也不把两路当作 R/Xc 或 50/250 kHz。普通体重设备、手动和健康导入仍不触发默认身体成分规则。

开源实现只作为研究线索：[openScale StandardImpedanceLib](https://github.com/oliexdev/openScale/blob/master/android_app/app/src/main/java/com/health/openscale/core/bluetooth/libs/StandardImpedanceLib.kt)采用 Sun 等公式，但并未完成儿童水分分支；[xiaomi_mi_scale](https://github.com/lolouk44/xiaomi_mi_scale/blob/master/src/Xiaomi_Scale_Body_Metrics.py)的宽年龄输入及限幅不等于全年龄验证；[Bodymiscale](https://github.com/dckiller51/bodymiscale/blob/main/custom_components/bodymiscale/metrics/impedance.py)包含设备经验适配。本实现根据文献独立编写，未复制这些项目的实现代码，也不以其存在作为 AFU 验证证据。

### 首页指标状态

状态依据未四舍五入的数值和测量日期对应的年龄计算，与卡片展示值共用同一成员和记录。首页、指标编辑页及拖动预览使用相同规则。状态标签仅展示，不提供点击跳转；标签不表示诊断或测量准确度，孕期、运动员等特殊人群不宜直接套用。

| 指标 | 规则与边界 | 来源与限制 |
| --- | --- | --- |
| BMI | 19 岁起：`<18.5` 偏低；`18.5 ≤ BMI <25` 标准；`25 ≤ BMI <30` 超重；`≥30` 肥胖 | [WHO 成人分类](https://www.who.int/data/nutrition/nlis/info/malnutrition-in-women)，包含老年人；不是中国成人切点 |
| 儿童 BMI | 低于 −3 SD 严重偏低，低于 −2 SD 偏低；0–60 月龄高于 +1/+2/+3 SD 分别为超重风险/超重/肥胖；61 月龄至未满 19 岁高于 +1/+2 SD 为超重/肥胖；等于切点不归入更严重档 | [WHO 儿童标准](https://www.who.int/toolkits/child-growth-standards/standards/body-mass-index-for-age-bmi-for-age)及[青少年参考](https://www.who.int/tools/growth-reference-data-for-5to19-years/indicators/bmi-for-age)，按性别和测量时年龄计算 |
| 体脂率、脂肪量 | 20–39 / 40–59 / 60–79 岁男性的三个切点依次为 `8/20/25`、`11/22/28`、`13/25/30`%；女性为 `21/33/39`、`23/34/40`、`24/36/42`%。低于第一切点为偏低；其余依次标准、偏高、很高，切点归入较高档。脂肪量沿用同次体脂率分级 | [OMRON BF508 说明书第 10 页](https://www.omron-healthcare.com/storage/im-hbf-508-e-en-06-02-2017.pdf)，依据 [Gallagher 等研究](https://pubmed.ncbi.nlm.nih.gov/10966886/)，属于应用采用的参考表，不是 WHO 统一体脂标准，也不证明 AFU 算法已经验证 |
| 水分率、水分量 | 成人男性 `50–65%`、女性 `45–60%`（包含端点）为标准；范围外偏低或偏高。水分量沿用同次水分率分级 | [TANITA Europe 公开参考](https://tanita.co.uk/understanding-your-measurements)，不是脱水诊断阈值 |
| 肌肉量、肌肉率 | Withings 20–79 岁性别/年龄区间，见下表 | 总肌肉产品参考，不是骨骼肌或肌少症阈值；跨设备适配未验证 |
| 骨量、骨量占比 | 男性 3%–5%，女性 2.5%–4%，包含端点 | Withings 产品参考；应用限制成人，不是骨密度分级 |
| 内脏脂肪 | 暂无分级 | 厂商指数尺度不同；应用经验指数未建立与厂商尺度的对应关系，不套用其他品牌的 9 或 12 等切点 |
| 基础代谢 | 暂无分级 | 个体能量需求估算没有适合当前数据的统一健康高低切点，不把高代谢判为“优” |

缺失值显示“无数据”，非有限值或非正数显示“数据异常”，超出分级年龄范围显示“不适用”；不会以默认“标准”代替无法判断的状态。BMI 可由普通体重记录和成员身高计算，不触发其他身体成分补算。

兼容已发布配置：仅当持久化指标顺序尚不包含 BMI 时，首次解码加入 BMI 并默认展示，其余顺序、可见性与成员资料保持不变。新配置中明确隐藏 BMI 的设置会保留；不重置存储或修改测量记录。

### 健康权限请求

开启“与 Apple 健康同步数据”时统一请求体重与体脂率的读写权限，下方共享与获取开关仅控制数据流，不重复请求授权。关闭总开关会暂停读写并保留配置。体重为导入记录的必需字段，体脂率可选。界面显示体重与体脂率的写入权限，状态相同时合并展示；不据此判断读取权限，也不根据空查询结果推断用户拒绝授权。

当前第 1 版配置包含 Apple 健康同步总开关 `appleHealth.isSyncEnabled`。所有非可选配置字段必须完整提供，缺失字段不会按旧开发格式补默认值；未选择的用户、设备通信规则等业务可选值仍可省略。不提供旧配置迁移或兼容读取。

## 健康指标展示

首页健康指标卡片均可点击打开说明弹窗，包含当前指标、数值、分段范围及位置标记；不显示成员信息、设备、时间或参考链接，参考来源集中在数据说明页面；无数据时显示 `--`，仍可阅读说明。没有统一阈值的项目说明其分级限制，不生成额外健康判断。

### 扩展指标与分级证据

骨骼肌、皮下脂肪、蛋白质的质量与比例不再列入展示和可选指标。设备已提供的原始字段保留在记录及导出文件中。

| 指标 | 可采用的参考及年龄 | 实现边界 |
| --- | --- | --- |
| 肌肉量、肌肉率 | Withings 20–79 岁性别/年龄区间，见下表 | 总肌肉产品参考，不是骨骼肌或肌少症阈值；跨设备适配未验证 |
| 骨量、骨量占比 | 男性 3%–5%，女性 2.5%–4%，包含端点 | Withings 产品参考；应用限制成人，不是骨密度分级 |
| 内脏脂肪 | 厂商指数定义不同，应用当前为自定义指数 | 无证据证明可套用 OMRON/TANITA 或其他应用等级边界，不显示评级标签 |
| 去脂体重 | 男性 FFMI 低于 17、女性低于 15 kg/m² 为偏低；其余未偏低 | 成人 ESPEN 低值参考，不单独诊断营养状态 |
| 基础代谢 | 年龄、性别、体型依赖的能量值 | 不做高低分级，不显示评级标签 |

记录文件保持既有 schemaVersion，列尾追加六个可选原始字段，接受已发布的旧 15 列文件；旧数据不重置。旧版应用不能读取新增列，升级后的应用可读取两种列布局。读取首页配置时移除已撤下的指标，保留其他指标的顺序与可见性。

数据说明页面精简为“数据来源”“计算方法”“参考资料”三部分；计算方法仅说明补算条件、资料使用及用途限制。完整公式和年龄分支保留在本文档中，应用不再展开长篇公式与指标状态表。参考资料保持直接外链，不新增文献子页面或离线原文副本。

### 应用采用的补充分级参考

这些规则只评价已有数值，不增加无阻抗记录的补算。厂商参考不能视为国际统一医学标准，应用的总肌肉与骨量经验估算尚未经过跨设备校准。

| 性别 | 年龄 | 总肌肉率参考范围（含端点） |
| --- | --- | --- |
| 男 | 20–39 岁 | 75%–89% |
| 男 | 40–59 岁 | 73%–86% |
| 男 | 60–79 岁 | 70%–84% |
| 女 | 20–39 岁 | 63%–75.5% |
| 女 | 40–59 岁 | 62%–73.5% |
| 女 | 60–79 岁 | 60%–72.5% |

肌肉、骨量的百分比范围乘本次体重换算质量范围，端点属于标准，范围外分别偏低或偏高。高值不称为“优”。去脂体重低值界限为男 17、女 15 乘以身高（米）的平方；达到界限显示“未偏低”，不是“营养正常”。

骨量原表没有分年龄；18 岁起是应用选择的使用范围，不表示厂商验证了全部成人年龄。肌肉不外推到 20 岁以下或 80 岁及以上，其他新增参考不外推到儿童。内脏脂肪的应用指数不能套用其他厂商等级，基础代谢仍不评级。新增去脂体重卡片在旧配置缺失时追加，保留用户排序与之后的隐藏选择。

- [Withings 总肌肉与骨量参考](https://support.withings.com/hc/en-us/articles/218500778-Body-What-are-the-normal-ranges-for-body-composition)
- [ESPEN 成人营养评估共识](https://www.clinicalnutritionjournal.com/article/S0261-5614%2815%2900075-8/fulltext)

### 计算说明的页面组织

数据说明主页仅展示数据来源、计算优先级与指标入口。优先使用通信协议解析后的设备值或录入/导入原值；同成分质量与比例可按体重换算；仍缺失的指标只有满足有效主阻抗、年龄和成员资料条件时才进入默认补算。BMI 独立计算，质量比例换算不等于启动阻抗模型，现有协议字段解析不是独立的第三套身体成分算法。

每个健康指标（包含 BMI 和静息能量消耗）都有独立计算页，按首页默认指标顺序排列，展示当前实现的公式、适用条件及对应资料。文献模型和应用经验系数明确区分；参考资料可能支持计算、定义或分级，不暗示某个经验系数已经验证。原集中参考列表移到各项目底部；同一资料可被多个项目引用。资料链接仍直接打开原网址，不缓存原文或复制第三方全文。页面不展示成员个人信息。
